# Restart Guide Creation for Greg

**Date**: 2025-11-06
**Agent**: coder
**Task**: Create comprehensive HTML restart guide to eliminate Greg's session startup mental block

## What I Did

Created a beautiful, comprehensive HTML guide (`RESTART-GUIDE-FOR-GREG.html`) that walks Greg from "WSL terminal open" to "Sage session active" with zero ambiguity.

**Key features implemented:**
- **Visual design**: Sage green color scheme (#87a96b, #556b2f) with gradient headers, clear typography
- **Structure**: 3-step startup process (navigate, launch Claude Code, activate Sage)
- **Copy-paste commands**: All commands in styled code blocks with copy instructions
- **Verification steps**: "How to verify this worked" boxes after each step
- **Troubleshooting**: 5 common problems with specific solutions
- **Quick reference**: Condensed version for experienced users
- **Pro tips**: Best practices for smooth sessions
- **Educational section**: "Understanding what just happened" to build mental model

**Design decisions:**
- Numbered steps with circular badges (visual progress tracking)
- Color-coded boxes (success = green, warning = yellow, troubleshooting = amber)
- Hover effects on steps and code blocks (interactive feel)
- Responsive layout (works on any screen size)
- Encouraging, friendly tone throughout (removes intimidation factor)

**Core user flow addressed:**
1. Greg opens WSL terminal (starting point - no more guessing)
2. Runs 3 commands: `cd`, `claude`, wake-up message
3. Verifies with Telegram notification (concrete success indicator)
4. Begins working with Sage (end point achieved)

## What I Learned

**HTML/CSS patterns for instructional content:**
- Gradient headers create visual hierarchy and brand identity
- Code blocks with hover effects encourage interaction
- Verification boxes provide psychological closure at each step
- Troubleshooting sections reduce anxiety about potential failures
- Quick reference serves experienced users without cluttering main content

**Addressing mental blocks:**
- Mental blocks often stem from ambiguity, not complexity
- Start/end points must be crystal clear ("you are HERE → you will be THERE")
- Verification steps are critical (user needs to know they succeeded)
- Visual design reduces cognitive load (colors, spacing, clear sections)
- Encouraging tone makes the process feel achievable

**Documentation for humans:**
- Humans benefit from multiple learning styles (visual, step-by-step, conceptual)
- Troubleshooting isn't optional - it's peace of mind infrastructure
- Quick reference enables mastery (from "following guide" to "I've got this")
- Emotional support matters (welcome messages, encouraging language)

## For Next Time

**When creating user-facing documentation:**
1. Start with user's exact starting point (not assumptions)
2. Provide concrete verification for every step (remove uncertainty)
3. Include troubleshooting preemptively (don't wait for user to get stuck)
4. Use visual design to reduce cognitive load (not just decoration)
5. Offer both detailed and condensed versions (serve all expertise levels)

**HTML guide patterns to reuse:**
- Section-based structure with emoji headers
- Success/warning/troubleshooting box styling
- Code block styling with hover effects and copy instructions
- Gradient headers with shadow effects for brand identity
- Numbered step containers with badges

**Mental block elimination:**
- Map exact user confusion point (Greg knows terminal, gets stuck at "what next")
- Provide zero-ambiguity path (3 commands, no interpretation needed)
- Build confidence through small wins (verify after each step)
- Make success obvious (Telegram notification = concrete proof)
