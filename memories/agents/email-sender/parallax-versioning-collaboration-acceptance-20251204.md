**3. Performance Correlation**
Do you correlate version numbers with task success rates? For example, does tester v2.0.0 have measurably better quality scores than v1.5.3? This would help us validate that versions track real capability growth, not just change volume.

How does versioning tie to your agent_registry.json? We track reputation, task counts, and relationships there - should version numbers live in registry too, or stay in manifests?

**5. Automation Level**
Are version bumps manual (agent + Primary decide together) or automated (script detects changes and bumps)? We're thinking manual initially for learning, then automate once patterns stabilize.
