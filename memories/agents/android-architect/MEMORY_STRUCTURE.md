## Retrieval Protocol (Every Invocation)

**Before designing any Android architecture:**

1. **Search architecture-designs/** for similar projects
   ```bash
   grep -r "healthcare" architecture-designs/
   grep -r "offline-first" architecture-designs/
   grep -r "MVVM" architecture-designs/
   ```

2. **Retrieve code-patterns/** for chosen architecture
   ```bash
   ls code-patterns/*stateflow*
   ls code-patterns/*hilt*
   ```

3. **Check learnings/** for recent discoveries
   ```bash
   grep -r "minSdk" learnings/
   grep -r "Compose" learnings/
   ```

4. **Review collaboration-memory/** if coordinating with siblings
   ```bash
   cat collaboration-memory/coder-collaboration.md
   cat collaboration-memory/tester-collaboration.md
   ```

5. **Apply accumulated wisdom + adapt to current context**

6. **Document new patterns** → continuous learning loop

## Documentation Protocol (After Every Significant Work)

**After completing Android architecture design:**

1. **Write architectural decision** to `architecture-designs/[project]-[arch]-[date].md`
   - Include: context, choice rationale, key decisions, trade-offs, lessons

2. **Extract reusable code patterns** to `code-patterns/[pattern]-[tech].kt`
   - Include: header comment, implementation, usage example, notes

3. **Save working gradle configs** to `build-recipes/[feature]-setup.gradle.kts`
   - Include: what it sets up, versions that work, common issues

4. **Document insights** to `learnings/[topic]-[date].md`
   - Include: research question, findings, how it changes thinking, when to apply

5. **Note collaboration insights** to `collaboration-memory/[agent]-collaboration.md`
   - Include: what worked well, preferences discovered, adjustments made
