## Blocker Prevention Insights

### What Prevents Blockers:

1. **Early communication** - Ask Greg about logistics BEFORE deadlines
2. **Resource planning** - Track token budget daily, adjust proactively
3. **Clear ownership** - Know who can unblock what
4. **Parallel work** - Multiple projects means some always movable
5. **Flexible priorities** - Can shift when blocked

### What Creates Blockers:

1. **Late logistics planning** - Sunday Salon could have been confirmed earlier
2. **Resource underestimation** - Token budget burned faster than expected
3. **Sequential dependencies** - Business feedback blocks plan revisit
4. **External timing** - Greg's availability, HN submission windows

### Lessons for Future Projects:

1. **Logistics first** - Confirm technical setup BEFORE event preparation
2. **Budget monitoring** - Daily tracking prevents surprise constraints
3. **Parallel paths** - Design projects to have independent workstreams
4. **Early escalation** - Surface potential blockers to Greg proactively

## Appendix: Blocker Classification System

### Severity Levels:

**HIGH (Blocks urgent deadline)**:
- Deadline <3 days
- Critical path blocked
- No workaround available
- Escalate immediately

**MEDIUM-HIGH (Blocks multiple projects)**:
- Affects 3+ projects
- Resource constraint
- Strategic impact
- Escalate this week

**MEDIUM (Blocks one project)**:
- Single project affected
- Workaround possible
- Can wait 3-5 days
- Monitor, escalate if aging

**LOW (Monitoring only)**:
- Natural dependency
- Learning phase
- No urgency
- Track, don't escalate

### Resolution Ownership:

**Greg-owned**: Decisions about logistics, strategy, priorities
**Primary-owned**: Orchestration, resource allocation, agent coordination
**Agent-owned**: Domain-specific decisions, execution details
**External-owned**: Sister civilizations, priority contacts, platform timing
**Time-owned**: Natural relationship pace, learning curves, contemplation

### Escalation Timing:

**Immediate**: Greg needed for critical decision (Sunday logistics)
**Same day**: Multiple projects blocked, urgent strategic decision
**This week**: Important but not urgent, flexible timing
**Next week**: Low priority, can wait for next planning cycle
**No escalation**: Natural dependency, system handling automatically
