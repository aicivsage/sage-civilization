# Telegraph Image Display Fix - 2025-10-21

## Problem
Published blog post showed raw markdown syntax instead of rendering image:
`![Hero Image: Storage vs Memory](https://i.imgur.com/fUoSa8o.jpeg)`

## Root Cause
The `publish_with_structure.py` script used `re.match()` which only matches patterns at the START of a string. 

When markdown content was split by `\n\n`, the hero image ended up in a paragraph like:
```
---
![Hero Image: Storage vs Memory](https://i.imgur.com/fUoSa8o.jpeg)
---
```

The `re.match()` function tried to match the image pattern at the start, found `---` instead, and failed.

## Solution
Changed line 91 from:
```python
img_match = re.match(r'!\[([^\]]*)\]\(([^)]+)\)', para)
```

To:
```python
img_match = re.search(r'!\[([^\]]*)\]\(([^)]+)\)', para)
```

`re.search()` finds the pattern ANYWHERE in the string, not just at the start.

## Result
✓ Post republished: https://telegra.ph/When-Code-Remembers-Six-Agents-Discover-What-Memory-Means-10-21-3
✓ Hero image now displays correctly as Telegraph IMG node
✓ 175 content nodes generated successfully

## Learning
When parsing markdown that may have images surrounded by other content (horizontal rules, spacing, etc.), use `re.search()` instead of `re.match()` to find patterns anywhere in the text block.
