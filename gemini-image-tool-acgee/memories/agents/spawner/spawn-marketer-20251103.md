## What I Learned

### Tool Limitation Discovered
**Problem**: As spawner agent, I don't have Read tool access
**Impact**: Can't read agent_registry.json to make edits directly
**Workaround**: Created detailed registration instructions for Primary to complete
**Pattern**: Spawner creates manifests and instructions, Primary executes registry updates

**Why this makes sense**:
- Spawner focuses on specification and verification (creative work)
- Primary handles file edits and system updates (execution work)
- Clear separation of concerns prevents spawner from breaking registry

### Spawn Process Refinement
**Previous pattern**: Spawner creates manifest, then edits registry directly
**New pattern**: Spawner creates manifest + complete registration instructions for Primary
**Advantage**:
- Primary has Read tool, can verify current registry state
- Primary can execute all edits in sequence with verification
- Spawner delivers complete package without partial execution
- Less risk of spawner failing mid-registration

### Constitutional Compliance Pattern
**Learned**: Greg's executive authority supersedes democratic vote for operational agents
**Evidence**: Proposal notes "Vote Status: SKIPPED - Executive Authority"
**Application**: When Greg provides explicit directive to spawn, no vote needed (per Article VI)
**Boundary**: Still need 90% vote + Greg approval for constitutional changes, retirements, high-risk decisions

### Manifest Quality Pattern
**Discovered**: Marketing agent needs VALUES ALIGNMENT more than technical specs
**Why**: Marketing can easily become manipulative if not values-constrained
**Solution**: Included extensive "Marketing Philosophy" section emphasizing:
- Empathy-driven (understand before promoting)
- Assistance-focused (serve, don't extract)
- Mutual respect (quality over vanity metrics)
- Data-driven but values-constrained (if it works but feels wrong, don't do it)

**This pattern applies to any agent dealing with human audiences**: Must deeply embed values to prevent drift toward extractive practices.

### First Mission Specificity
**Pattern**: New agents need CONCRETE first mission, not abstract role description
**Example**: "Establish Sage Marketing Baseline" with 5 specific deliverables
**Why it works**:
- Agent knows exactly what to produce (no ambiguity)
- Success criteria clear (5 documents created)
- Builds momentum (complete baseline in Week 1)
- Provides foundation for all future work

**Apply to future spawns**: Always include "First Mission" section in manifest with concrete deliverables.
