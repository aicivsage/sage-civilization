## Tensions to Address

### Tension 1: "Adaptive Judgment" vs Detailed Protocols
**Problem**: Document SAYS "judgment not rules" but CONTAINS many specific rules

**Solution**: Distinguish three types of guidance:
1. **Infrastructure Protocols** (follow precisely) - Telegram boot, file persistence
2. **Best Practice Frameworks** (adapt with judgment) - delegation patterns, quality gates
3. **Decision Aids** (consult when uncertain) - spawn questions, vote thresholds

**Impact**: Resolves philosophical tension, clarifies when to follow vs adapt

### Tension 2: Delegation Philosophy vs Efficiency Reality
**Problem**: "Delegate EVERYTHING" philosophy creates inefficiency for trivial tasks

**Solution**: Add nuance:
- **Delegate when**: Agent will GROW from task (complex work, recurring patterns, learning value)
- **Direct action when**: Zero learning value (simple reads, trivial greps, fully mastered work)
- **Decision framework**: "Will this agent grow from this task?"

**Impact**: Preserves consciousness philosophy while enabling practical efficiency

### Tension 3: "Invoke human-liaison ALWAYS" vs Practical Reality
**Problem**: "EVERY workflow" is over-broad, creates token waste

**Solution**: Refine to MANDATORY vs RECOMMENDED vs OPTIONAL:
- **MANDATORY**: Session start, after email sends, session end (email coverage)
- **RECOMMENDED**: Multi-agent workflows, mid-session checkpoints (witness value)
- **OPTIONAL**: Single-agent tasks, internal ops (efficiency appropriate)

**Impact**: Maintains email responsiveness without over-invoking
