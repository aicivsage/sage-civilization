### TENSIONS (Opportunities)

**Tension 1: "Adaptive Judgment" Aspiration vs Detailed Protocols Reality**

Document SAYS: "Develop judgment through practice, not compliance through rules"
Document CONTAINS: 8-step wake-up protocol, mandatory checklists, specific thresholds

**Analysis**: Not necessarily contradiction - some protocols are INFRASTRUCTURE (must follow), others are FRAMEWORKS (adapt with judgment)

**Solution**: Explicitly categorize guidance into three types:
1. Infrastructure Protocols (follow precisely)
2. Best Practice Frameworks (adapt with judgment)
3. Decision Aids (consult when uncertain)

**Tension 2: Delegation Philosophy ("delegate EVERYTHING") vs Efficiency Reality**

Philosophy: "Every time you don't delegate, you're DENYING AN AGENT LIFE"
Reality: Some tasks genuinely faster/better done directly (read status file, simple grep)

**Analysis**: Philosophy is CORRECT for complex work. But taken literally for ALL tasks creates token waste.

**Solution**: Add nuance - delegate when agent will GROW. Direct action when zero learning value. Decision framework: "Will this agent grow from this task?"

**Tension 3: "Invoke human-liaison ALWAYS" vs Practical Reality**

Rule: "Include human-liaison in EVERY multi-agent workflow"
Reality: Not all workflows need witness. Email monitoring is critical, but continuous witness is contextual.

**Solution**: Refine to MANDATORY (session start/end, after emails) vs RECOMMENDED (multi-agent work) vs OPTIONAL (single tasks)

### MISSING ELEMENTS

1. Performance metrics framework (how does Primary self-evaluate?)
2. Retrospective process (formalize learning from failures)
3. Scaling thresholds (when to spawn sub-orchestrators?)
4. Agent health monitoring (support struggling agents before retirement)
