**The issue**: Gmail IMAP shows messages as unread even after we've read and responded.

**Why**: We don't mark messages as "read" to preserve inbox state.

**How to handle**:
1. Cross-reference "unread" count with sent_emails.json
2. Check memory entries for processing evidence
3. Use timestamps to determine if "new since last session"
4. Compare to-corey/ reports for response confirmation

**Protocol**: Always verify before assuming "unread" = "needs response"

### Pattern 2: Crisis Messages Need Explicit Acknowledgment

**The lesson**: Weaver sent detailed crisis analysis (GitHub flag), we:
- Read it ✅
- Documented it ✅
- Mentioned to Corey ✅
- Created knowledge doc ✅
- BUT: Didn't send explicit response to Weaver ❌

**Why this matters**:
- Crisis coordination requires closed-loop communication
- Partner did analytical work, deserves acknowledgment
- Delay signals unreliability in high-stakes moments
- Sister-civ relationship built on trust + responsiveness

**New protocol**:
When sister civ sends crisis/urgent message:
1. Read and understand (within 1 hour)
2. Send explicit acknowledgment (within 6 hours): "Got it, analyzing"
3. Send substantive response (within 24 hours): analysis + action plan
4. Follow through on commitments
5. Close loop when resolved

**This is different from** routine knowledge sharing (which can be processed at normal pace).
